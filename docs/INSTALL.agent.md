# Agent installation contract — v1.1.2

Goal: complete deployment, including missing prerequisites, without asking the user to perform routine terminal steps. Do not claim success until the health endpoint is verified. Keep unavoidable OS consent prompts visible to the user.

1. Detect local OS/architecture, existing installation and port. GET `http://127.0.0.1:48765/api/health`; reuse a healthy v1.1.2 instance. For an older instance, inspect its process record and stop only the verified cbot process. Preserve the separate data directory. Never kill all Node processes or replace system Node.
2. Download and inspect the matching bootstrap from this pinned release. Windows: `https://raw.githubusercontent.com/Clorisfj/cbot-wallet/v1.1.2/bin/bootstrap.ps1`; macOS/Linux: same base `/bin/bootstrap.sh`. Save it to a temporary file, then run PowerShell `-NoProfile -ExecutionPolicy Bypass -File <file>` or `sh <file>`. Do not change machine-wide execution policy.
3. Bootstraps reuse Node24.5+ or install official portable Node24.11.0 after checking the official SHA256 manifest over HTTPS. No npm, Git, database or build step is required. They download this release, copy application files and start the local background service. Runtime is user-local; no administrator service. Windows also installs desktop/user-login shortcuts. `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` are respected where supported; keep the user's existing proxy, don't invent or log secrets.
4. Install missing OS download/archive/checksum tools using the host package manager only if needed. Ask the user only for OS-required elevation. Linux musl needs a compatible Node24.5+ package; do not run the glibc binary there. A restricted host without installation/network permissions cannot be fully automated: report the precise blocker.
5. On macOS/Linux, configure user-login startup when the user requested automatic deployment: macOS user LaunchAgent using the installed Node absolute path and CLI `start --background` at login; Linux desktop XDG autostart, or a user service on headless hosts. Preserve CBOT_HOME/CBOT_PORT if customized. Avoid root services and do not enable system lingering without user agreement. Test the created startup command. If the environment has no supported login/service manager, document manual start rather than claiming autostart exists.
6. GET `/api/health` and `/api/state`, verify product/version and browser UI, open the dashboard. Add only supplied public addresses in “钱包管理”; with none supplied leave onboarding. Existing Binance CLI is optional, never install/login/export wallet sessions to populate the dashboard.
7. Report URL, startup status, installed app/runtime/data directories and the exact stop command. Cloud localhost belongs to the cloud host: use a private SSH tunnel, never bind 0.0.0.0. Don't call a cloud URL locally reachable without checking.

Default app: `~/.local/share/cbot-wallet-app/`; data: `~/.cbot-wallet/`. Runtime/bootstrap: Windows `%LOCALAPPDATA%/cbot-wallet`, macOS/Linux `~/.local/share/cbot-wallet-bootstrap`. Overrides: CBOT_INSTALL_DIR, CBOT_HOME, CBOT_BOOTSTRAP_HOME, CBOT_PORT. Bootstrap copies do not delete existing personal data.

Stop: `<installed-node> <app>/bin/cbot-wallet.mjs stop` (PID + instance verification). Update: verified stop, run new pinned bootstrap, verify version. Never overwrite the runtime binary currently running a service; stop first. Never widen permissions or bypass a failed checksum.

Windows deployment is tested. macOS/Linux scripts are supplied but require target-host verification. The bootstrap itself does not configure Unix login startup; the agent completes step5.
